# 深度逆向与真源求值高品质实战方法论 (Deep Reverse Engineering & Ground Truth Guide)

> **核心原则**：彻底摒弃“浮于表面抓几个 HTML class、点进去是空壳”的低质逻辑。
> 本指南指导 AI 工程师如何像专业黑客与爬虫架构师一样，深入挖掘站点的**真实数据源、移动端内部 API、免嗅探直链与全量沉浸式排版**，产出媲美官方原生体验的规则。

---

## 一、AI 逻辑质量低下三大根因剖析与工程对照

| 缺陷表现 | 低质逻辑根因 | 专业高品质工程实践 |
|---|---|---|
| **点进详情页是空壳或仅有一张封面** | 仅解析了列表卡片，未真正逆向详情页的图集/正文接口，或遇到 302 重定向就放弃。 | **全量展开深度穿透**：逆向出图文所有原图（`imageList`），排版为原生全屏大图瀑布流（`pic_1_full`）；完整呈现作者头像、发布时间、正文与互动数据。 |
| **视频点击无法播放或只有前 5 集** | 抓取了 PC 桌面端被防爬墙阻断的网页，或只拿到首屏缩略数据，没有处理异步分集 API。 | **真源直链与分页合并**：逆向小程序/H5 真实接口，获取完整 40+ 集列表；输出 `@lazyRule=` 并附加 `;{Referer@...&&User-Agent@PC}` 突破防盗链；结合免嗅探探针。 |
| **运行两下就报风控或 302 跳转登录** | 盲目请求反爬最森严的 PC 桌面端入口，缺少 Session 自愈或动态指纹。 | **移动端优先 + PC 引擎兜底**：优先使用防御最薄弱的移动端/小程序 API；遇高防反爬时自动联动 PC 本地 Python 爬虫引擎（`127.0.0.1:18000`）的无头浏览器池完成抓取。 |

## 二、高品质深度逆向五步法 (The 5-Step Deep Extraction)

### 1. 移动端与微信小程序 API 优先法则 (Mobile/Mini-App API First)
- **原理**：PC 网页端爬虫极多，各大厂（小红书、腾讯、B站、短剧平台）在此布设了极其繁重的滑块、设备指纹、代码混淆与 302 登录风控；
- **破局点**：移动端 H5（`m.xxx.com`）或微信小程序接口（`api.xxx.com/miniapp/...`）：
  - 数据结构 100% 纯 JSON；
  - 极少有弹窗与滑块；
  - 接口通常只要简单的固定 User-Agent 或伪造 `Referer` 即可免密通行。

### 2. 真实链路“真源”定位法
- **图文类真源**：
  必须找到包含原图数组的字段（如 `imageList`, `photos`, `images`, `pictures`）。
  提取每个原图的无水印直链（去除 `!thumbnail` 或 `!webp_mw` 后缀），统一排版为：
  ```javascript
  d.push({
      title: '第 ' + (i + 1) + ' 张',
      pic_url: highResImgUrl + '@Referer=' + host,
      url: highResImgUrl + '@Referer=' + host,
      col_type: 'pic_1_full'
  });
  ```
- **视频类真源**：
  必须找到真实的流媒体分发地址（`m3u8`、`mp4`、`flv`）或各大主流解析探针，严禁输出普通 html 页面作为播放直链。
  并且必须使用标准协议：
  ```javascript
  url: videoUrl + '@lazyRule=.js:(() => { return input + ";{Referer@' + host + '&&User-Agent@PC}"; })()'
  ```

### 3. 多层级深潜数据合并机制
针对电视剧、动漫、连载短剧：
- 详情页首屏只给 10 集时，必须在 `detail_find_rule` 内部根据 `cid` 或 `id` 循环或分页请求后续分集接口，直到 `has_more === false` 或达到安全上限（如 100 集）；
- 将完整的全集一次性合并呈现在选集列表，带给用户无断点的顺畅看剧体验。

### 4. 动态 Session / Cookie 自愈闭环
对于需要设备指纹的站点（如小红书、微博）：
- 可以在规则开头自动检测是否有本地存储的会话（`getItem('device_cookie')`）；
- 若没有或已失效，通过微请求先访问一次根地址，从下发的 `Set-Cookie` 中提取关键 token 并持久化，实现全自动静默自愈。

### 5. PC 端 Python 爬虫引擎全能兜底 (Synergy Protection)
当遇到移动端 JS 无法抗衡的极端反爬（如 Cloudflare 5秒盾、极验滑块、WebAssembly 加密参数）：
- 脚本中探测本地 `127.0.0.1:18000`；
- 调用 PC 端 Python 引擎的 `stealthy` 隐身浏览器池进行动态无头渲染；
- 直接拿取渲染完毕的完整页面，实现降维打击。

## 三、四大内容垂类的高品质交互排版规范

| 垂类 | 一级列表排版 | 详情页沉浸排版 | 选集与交互规范 |
|---|---|---|---|
| **图文社区 (小红书/微博/公众号)** | `movie_2` (双列瀑布流海报 + 作者 + 点赞) | 顶部大卡片（剧名契约）+ 作者名片 + 正文文本 + `pic_1_full` (全屏原图画册) | 点击图片支持原图缩放查看，视频笔记提供一键播放。 |
| **影视/长视频 (腾讯/爱奇艺/B站)** | `movie_3` (三列海报 + 评分 + 连载集数) | 顶部大卡片（标准剧名契约）+ 演职员简介 + 线路 Tab (`text_1`) | `text_3` 网格选集，支持多季级联，必须标准 `@lazyRule=`。 |
| **短剧/微短剧 (抖音/快手短剧)** | `movie_2` (双列高竖版海报) | 竖屏大卡片 + 全剧简介 | `text_4` 紧凑网格选集 (1-80集平铺)，MP4 竖屏播放器。 |
| **漫画/绘本 (快看/哔哩哔哩漫画)** | `movie_3` (竖版封面 + 最新话) | 章节目录 (`text_3` / `@rule=` 下潜) | 章节详情采用 `pic_1_full` 连续无缝上下滚动阅览。 |
