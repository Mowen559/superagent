# Design

## Decisions

1. 对工作区只读工具使用 `(canonical call fingerprint, workspace revision)` 身份。网络、用户询问、写工具保持原身份；规划元工具不能改变观察代次。实际写尝试（包括可能部分失败的写入）使观察过期；同代次重复仍有上限。
2. 验证分类仍由实际退出码与命令共同确定。增加 Node 原生测试与 Python unittest。RTK 只允许一层直接包装或 proxy；先拦截 shell 操作符、帮助/版本/收集参数，再检查解包后的质量命令。分类不会授予工具权限。
3. 评测复用现有 EvaluationModel 接口。每案例最多 10 轮、每轮 8 个调用、每请求 60 秒；CLI 将模型输出上限设为 1536。临时目录只暴露 README、settings.json、固定验收命令。写工具仅接受 settings.json 的有限 JSON，不提供 shell、网络或可执行代码写入。
4. 固定 Node 测试由受控工具真实启动，参数完全固定，输出写入临时文件，最多等待 5 秒并 kill/wait。模型不能修改测试；独立复验不会计入模型的验证收据。阶段一通过后注入第二条用户要求，旧验证立即失效，必须重新修改与验证。
5. 报告只保存合成对话、规范收据、配置摘要与真实模型身份，不保存凭据、Provider 错误原文或请求快照。不向 EvolutionMemory 自动写入未认证经验。每次 live 显式启动，离线 preview 不读取模型配置。

## Risks and limits

合成配置任务不足以代表代码开发能力。组件评测不覆盖 AgentLoop 的压缩、黑板、动态工具和真实业务服务。固定夹具通过不能证明领域泛化；需保留失败记录和独立案例。RTK 分类不保证其二进制存在。

## Failure diagnosis

诊断提示是推断，不是执行证据。`Access denied` 只能提示检查本地 ACL 或远端授权；明确的 HTTP 防护特征只能提示查看响应和既有受支持 Provider，不能硬编码探测本地服务。缺失 `window/document/fetch` 先检查真实 Node/SSR/Worker/沙箱环境，再依据工程事实选 API。

## Live evaluation follow-up

Gemini 首轮执行对话两案例通过，但规划对照中增强模式在 4 轮内连续读取、未提交计划。保留原始失败报告，不增加轮次或放松验收。CognitiveRuntime 公开实际剩余预算，并允许调用方只降低、不能提高上限；引导合并独立只读调用、复用已提供事实、将真实缺口标为待查问题。规划评测向两个变体投影相同的 4 轮截止约束，并明确保留一轮处理追加要求；增强认知也使用相同上限，避免隐含 40 轮误导。两个变体的流程状态独立记录；CLI 在有未完成变体时必须非零退出，词面覆盖仍只作代理指标。
