基线：`1d267bfec29f53bbb6a0f7e91ea14082caca336a`，2026-09-07。审查开始时 Git 工作区干净；本轮只整理文档和审查证据，不修改产品源码。

## 1. 判断与证据范围

**当前尚未整体符合目标架构。** 代码已从大文件逐步迁移到目录，部分稳定接口已经存在；但业务用例、路径授权、凭据刷新和存储知识仍跨边界分散。不能因为出现 Runtime、Guard 或 Transaction 名称就认定对应不变量已成立。

检查范围：清点 `src/` 下 274 个 Rust 文件；读取入口/装配及九个领域的代表性接口、关键调用点和风险流程；检查 Cargo 根包与 snow-crates 依赖结构。没有逐行审查全部实现，也没有构建完整动态调用图。codebase-memory-mcp 未索引且 fast 初始化失败，按回退规则进行源码读取和文本定位；文本命中仅用于证据导航，不作完整语义图。

判断口径：局部符合表示所列契约存在实现；部分符合表示机制已有但跨域仍有缺口；未符合表示已找到明确反例；未认证表示未执行相应环境测试。没有用文件数或行数推算“DDD 完成百分比”。

## 3. 具体发现

### A1 / P1：QA 没有消费 Workspace Capability

证据：[routes/qa.rs](../../src/routes/qa.rs)，`playwright_run` 第 66 行起读取 `body.project`，第 80～86 行直接 `Command::new` 并设置 cwd；处理器提取的是 `_state`，没有调用 workspace registry。list/record/k6 同类入口也需要纳入整改。

影响：已打开工作区的准入规则不能约束该路径；QA 子进程不通过共享 Task/取消/超时用例。不能由其他文件新增 Guard 推导“所有 OS 操作已统一”。

目标：Verification/QA 用例接收已授权 Workspace，启动有界 Adapter，并返回验证收据。验收：未登记根、越界 spec、超时、取消、输出上限；只测试构造命令不够。

### A2 / P1：DestructiveOps 校验的路径不是唯一执行来源

证据：[destructive_ops.rs](../../src/services/destructive_ops.rs) 第 13～46 行。对象持有 Guard，但 `git_restore`、`shadow_rollback`、`apply_patch` 仍接收独立 `project: &str`；计算 `safe_project` 后，底层调用仍使用原始 project。

这是接口不变量缺失，不等于本轮已演示所有 HTTP 调用都能越权。当前审阅的 Git restore route 先从 registry 解析再创建 Guard，两者通常对应同一项目；但服务 API 没有强制这种关系，新调用点可错配。

目标：移除重复 project 参数，底层只消费绑定授权的规范根。验收：Guard 指向 A、参数尝试指向 B 时无法构造执行请求；同时覆盖删除文件恢复，不把“文件必须当前存在”误当所有写操作的要求。

### A3 / P1：同步版本检查不在锁内

证据：[config_sync/coordinator.rs](../../src/services/agent/config_sync/coordinator.rs) 的 `execute_sync`，先 inspect/revision check/plan，之后才 `tx.lock` 与 snapshot。目标在检查与锁之间变化时，计划仍可能写入。调用者不遵守锁文件协议时还需额外冲突检测。

同文件多个分支使用 `let _ = tx.rollback()`；[transaction.rs](../../src/services/agent/config_sync/transaction.rs) 的 rollback 依据快照恢复，未检查当前版本是否仍是本次写入版本。锁文件采用 create_new，崩溃后的锁恢复也需明确。

目标：加锁后重新 inspect 并核对 revision，再提交；回滚使用写后指纹并返回恢复结果。失败 Receipt 区分原错误、部分写入和回滚失败；不能只返回统一失败掩盖外部状态。

### A4 / P1：身份生命周期尚未集中

证据：[cli_auth/server.rs](../../src/services/cli_auth/server.rs) 第 107 行 `rx.await` 无显式 callback deadline；第 151～152 行 Token 解析错误拼接原始响应；`handle_callback` 先 take sender 再校验 state。

此外 [proxy/dispatch.rs](../../src/routes/proxy/dispatch.rs) 第 110～165 行和 [llm_provider/mod.rs](../../src/services/llm_provider/mod.rs) 第 348 行起分别执行凭据读取、刷新及保存流程。不同调用路径可能形成不同恢复策略。

目标：Credential Provider 拥有刷新互斥及保存，AuthRuntime 拥有登录 deadline 和回调状态；网关只拿受限凭据与错误分类。验收使用本地 OAuth mock，不需要真实用户账户。

### A5 / P1：停机取消不等于资源 drain 完成

证据：[server.rs](../../src/server.rs) 的 `shutdown_signal` 调用 `cancel_all_active_tasks` 后立即打印 drained successfully；[task_manager.rs](../../src/services/task_manager.rs) 第 407 行起只是遍历任务调用 cancel_task，没有 await/join Adapter。

Axum graceful shutdown 负责 HTTP 连接排空，不能自动证明 detached Agent、媒体编码器或 Worker 已回收。当前实现有进展，但不满足“有界等待资源完成”的目标。

目标：注册运行句柄，停止准入并广播取消，按 deadline 等待回收，对残留资源返回明确失败事实。测试持续运行 fake Child 和录制替身，验证停机后无遗留。

### A6 / P2：模型调用仍有两套应用流程

证据：proxy 的 `handle_request` 自己创建 ModelRouteRuntime/Health、遍历 candidates 并发送 HTTP；LlmProvider 也自行执行这些步骤。二者共享底层类型，不等于共享同一个业务用例。

目标：保留 inbound/outbound Converter，提取 Gateway 执行接口，输出 Canonical stream 与 Attempt Receipt。切换账户、错误恢复、能力过滤只能有一处业务规则。外部 CLI 自己直连厂商的流量不属于已治理范围。

### A7 / P2：项目理解仍暴露存储结构

证据：[code_intelligence.rs](../../src/services/code_intelligence.rs) 公开 `open_ro() -> Connection` 与 DB path；[requirement_analyzer.rs](../../src/services/requirement_analyzer.rs) 直接查询 nodes 表，并保留解析入口、图推演的 TODO；[reverse_engineering/engine.rs](../../src/reverse_engineering/engine.rs) 直接解析 DB 路径并访问 Supermemory。

目标：向规划暴露带版本 Evidence 和结构查询 DTO；Schema 与连接只由项目理解 Adapter 使用。存储目录移动不能解决这一边界。缺库时返回明确 unavailable/fallback，不把空结果或 Ok(()) 宣称完整分析。

### A8 / P2：录制缺少持久化生命周期

证据：[record_manager.rs](../../src/services/visual_pipeline/record_manager.rs) 使用 `ACTIVE_SESSION`、`LAST_EXPORT` 全局状态；已有 FFmpeg stop/export 和非空输出检查，但没有完整的 Recording 状态记录及重启恢复契约。

目标：停止采集、编码完成、Artifact 发布分别记录；设备和编码器由媒体域回收。UI 调用不得直接改变录制内部字段。此处不否认当前本机录屏可运行，也未进行桌面采集认证。

### A9 / P2：当前封装方式仍与设计相反

证据：源码清单记录 37 处 `pub use ...::*`；`provider_capability_runtime/` 中 15 个策略常量在 8 个文件重复定义；新 builtin、knowledge_corpus 等 facade 也继续通配导出。

目标：私有子模块、显式兼容导出、单一策略对象。收口以公共调用点和契约测试为依据，不一次性取消所有现有 public 路径。
