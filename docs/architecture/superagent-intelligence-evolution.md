日期：2026-10-29。用户优先级：需求理解、复杂任务拆解、主动补齐上下文。

## 对比范围与依据

比较可审阅的运行机制，不以功能数量或宣传文案推断任务成功率。

| 参考项目 | 已核对的一手来源 | 本项目发现的差距 | 本次处理 |
|---|---|---|---|
| OpenHands SDK | [StuckDetector 源码](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/stuck_detector.py) 检查动作/观察、错误和交替循环 | 原有保护只看完全相同的工具参数，修复后重复质量检查也可能被拦截 | 质量检查身份加入工作区修改代次；无修改的重复仍有限制。语义循环和交替结果检测仍待实现 |

| Codex | [Agent loop 工程说明](https://openai.com/index/unrolling-the-codex-agent-loop/) 描述指令、工具、输入与观察如何进入下一次模型请求 | 已有认知状态，但工作区概览凭目录名注入固定 Spring/MyBatis/Next.js 规则；具体需求仍缺稳定的子目标表示 | 主动提供真实仓库摘录，移除虚构的框架约束；将模型编写的 Task Contract 保留在每轮认知上下文 |

以上是机制对照，不构成跨模型、跨项目的性能排名，也不表示已经达到这些项目的整体能力。

## 实际改动

### 需求理解与子目标

`DynamicIntentEngine` 改用实际执行动词识别执行目标，保留只读约束的优先级。解释代码不再仅因出现“代码”而进入实现模式；“进化”“提升”等请求进入执行路径。普通 `model` 等词不再被映射成虚构的微服务。英文关键字按词边界匹配，避免 `latest` 被当作 `test`。

新增纯规划工具 `plan_task`，在共享 AgentLoop 装配时注册，所有使用此装配的调用入口都能发现。模型负责语义理解，Rust 运行时负责约束结构：

- 目标解释和 1～6 条可观察的成功条件。
- 显式约束与 1～8 个有验收条件的子目标。
- 唯一子目标 ID；依赖只允许指向更早的步骤，阻断自依赖、前向引用和循环。
- 最多 6 个待查问题，来源为 `workspace`、`external` 或 `user`。

工具不访问文件、不调用额外模型、不修改权限。规范结果写入现有 Tool Call/Tool Result 账本，并由 CognitiveRuntime 在当前 Run 的后续轮次重新投影；重新提交完整计划即可修订。新 Run 从空 Task Contract 开始。规划和 Todo 更新不计入工具证据或代码变更。

第一阶段的 Task Contract 是模型假设，尚不提供逐子目标证据绑定。[第二阶段](superagent-task-evidence-and-evals.md) 增加了 Run 内收据绑定和完成门禁；业务验收语义仍需模型和实际测试核对。当前不恢复跨进程中断 Run 的规划状态。

### 主动补齐上下文

Run Prelude 在第一次模型调用前读取当前工作区的 `AGENTS.md`、`CONTEXT.md`、`README.md` 和已知构建清单。有以下边界：每文件最多读取 16,385 字节、投影约 600 字符，所有摘录合计最多 3,000 字符；保留文件名、行范围与 `truncated` 标记；通过现有路径解析器限制工作区范围。

目录概览只报告真实目录和根清单，限制扫描条目和目录数量，标记截断。发现 `pom.xml` 只能说明 Maven 清单存在，不能据此声称 Java 版本、Spring 或 MyBatis。不存在的工作区不再回退到进程 cwd。

认知指导要求先调查可自行确定的事实，再询问仍影响范围或行为的选择。简单请求直接执行，复杂请求使用 Task Contract。没有额外的联网请求或独立规划模型调用。

### 执行结果与完成门禁

Gateway 在压缩前规范化 `run_command` 和 `verify_task_tool` 的非零退出码、失败/超时状态与显式失败标志。只有明确的前台质量命令及成功退出码形成验证收据；帮助、列举、收集、组合命令和后台启动不能作为完成证据。

两个执行分支均改为向 CognitiveRuntime 传递完整收据。ReadOnly/Network/ProcessControl 风险本身不再代表验证成功。新写操作、可能部分写入的失败和进程检查失败会使旧验证失效。纯验证任务不要求额外写文件。

复核最多一次；再次尝试结束时仍有证据缺口则 Run 失败，Fast 模式同样不能绕过。失败路径记录失败进化结果，避免把未完成工作作为成功经验积累。

质量命令识别仍是保守白名单，不能证明所有测试脚本都具有有效断言；业务验收和真实模型表现需要单独评测。
