## A阶段先改什么

1. 已注册角色只显示registered，管理器就绪与执行器就绪分开。未接线时health为unverified，healthy=false，运行数不能取角色目录数量。
2. spawn/shutdown未接执行器时HTTP 501、ok=false和稳定错误码；不创建虚假运行节点或伪造进程终止。
3. 所有预置步骤待执行且没有虚构的spec_approved结果。execute没有真实执行器时拒绝，步骤/输出/更新时间均不变；空流程不能成功。
4. 黑板和能力矩阵明确进程内存/未验证，保留既有JSON主要字段，文档先于代码；无GUI与真实模型认证声明。

A阶段只消除虚假成功，不表示蜂群已能完成任务。B阶段复用SubagentRuntime，先限制每父2个并行，蜂群子任务不递归委派；工作区隔离失败不能降级为共享目录。子任务成功文字、拓扑、心跳、队列入队均不代替产物及验证收据。

## 如何判断记忆真的有用

每次Run给出stored/skipped/rejected/failed和原因；用来源项目身份保存，与临时执行目录分开。只从匹配的工具调用、实际修订和验收收据提炼候选；只读任务不自动写可召回经验。新Session和重启后的真实任务须使用同一有效记录，并接受撤销、版本变化与跨项目隔离检查。未经不同目标留出验证，候选不能进入正式Skill。

## 模型、范围与成本

沿用已授权gemini-3.8-flash-high，不读取/输出密钥，不修改用户模型配置。A阶段以离线和无界面API验证为主。B/E真实任务冻结模型/二进制/Skill/预算，子模型调用计入总预算；近期单次调用曾160～172秒，在线任务使用能覆盖必要轮次的有界时限，保留超时与地区/账户阻塞。这里不承诺固定耗时或“所有应用都能逆向”。不操作桌面，不改已验动漫规则或云条目，不新增外发。
