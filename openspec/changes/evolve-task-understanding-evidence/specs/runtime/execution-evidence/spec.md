# Spec Delta

## Purpose

为自主执行提供可验证的完成边界，区分工具正常返回、代码修改、前台质量验证及任务完成；在后续修改、新要求、失败检查和回滚发生时，防止旧证据继续支持错误的成功结论。

## ADDED Requirements

### Requirement: 规范化质量验证事实
系统 MUST 识别明确的前台质量命令及成功退出码才能记录验证成功；非零退出码、超时、后台启动、帮助和普通读取不能当作验证。别名与参数归一化后也必须执行相同判定。

#### Scenario: 工具返回结构化失败退出码
- **WHEN** 工具函数正常返回但进程退出码非零
- **THEN** 结果记录为失败，不推进成功验收或成功经验学习。

### Requirement: 验证新鲜度
系统 MUST 在后续写操作、失败进程检查或新增计划要求后撤销旧验证；允许在工作区或验证要求变化后重新执行同一质量命令，但无变化的重复仍受限。

#### Scenario: 成功检查后修改文件
- **WHEN** 已有成功验证但之后又修改文件或新增要求
- **THEN** 完成被阻止，必须取得变化后的新验证。

### Requirement: 所有成功结束路径共享门禁
系统 MUST 在正文结束、清单完成快捷结束及历史答复快捷结束前检查本轮范围、步骤与验证证据；快速模式、长正文、代码块或清单文件不能绕过门禁。

#### Scenario: 清单完成但代码未验证
- **WHEN** 所有清单项勾选完成而执行证据仍有缺口
- **THEN** 系统不能成功返回该清单附带的文本或此前的答复。

### Requirement: 有界复核与失败收敛
系统 SHALL 最多进行一次完成复核，仍缺证据时以失败结束；补充验证门禁重试耗尽不能转成成功。

#### Scenario: 复核后仍无证据
- **WHEN** 再次结束时仍有步骤或验证缺口
- **THEN** 系统返回失败并说明缺口，不记录成功进化结果。

### Requirement: 规划型范围与执行范围区分
系统 MUST 允许明确的只做方案请求交付有调查证据的提案，未来实施步骤无需本轮执行，也不得声称已经执行。

#### Scenario: 仅要求当前仓库改造方案
- **WHEN** 用户明确限定只做规划
- **THEN** 调查证据齐备后可交付提案，不能仅因方案包含未来修改步骤就强迫本轮写文件。
