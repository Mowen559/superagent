# Design

## Context

日期：2026-10-30。动机和范围见 [proposal.md](proposal.md)。这是待实施路线图；表中的指标均为目标，不是已取得的成绩。

主要依据：`docs/reviews/2026-10-30-skill-execution-audit.md`、`docs/reviews/2026-10-30-hub-native-capability-audit.md` 及所链接原始 JSON。既有 Rust/Node/TypeScript 回归结果仅证明对应工程检查，不折算为智能水平百分比。

当前结构已有 TaskContract、TaskProgress、工具网关、Run Prelude、SessionLedger、技能发现和记忆存储，优先补齐这些连接。代码图谱 MCP 本机检索未返回有效项目，已尝试索引；本次结合既有原生索引、定点源码和实测报告规划，不把 MCP 不可用误写成整个原生图谱不可用。

两个需专项复现的源码风险：worker 对隔离目录解析 origin 后可能将 origin 用为执行根；大结果存储器默认位置与读取工具注入位置可能不一致。前者需核对读知识与写代码的实际授权路径，后者需端到端超长输出测试；本计划不把静态疑点直接列为已复现漏洞。

## Goals / Non-Goals

**Goals:**

1. 用户给自然需求后，Hub 能形成合理交付目标、使用适合的能力、亲自实施、根据真实失败修正并交付可复用成果。
2. 先完成一条真实业务链，再扩大到正向开发、逆向分析、规则生成和失败恢复；每次提升都能复跑比较。
3. 完成状态、最终答复和物理证据一致。支持调查成果结题，也阻止“探针成功”被当成“规则交付”。
4. 原生 understand、外部 Understand、RTK、Supermemory 分别可观测、可停用、可比较，避免工具数量替代能力评价。
5. 全过程通过命令行、API、SDK、实际规则运行库及无界面解码测试；无须桌面自动化。

**Non-Goals:**

本轮路线不训练权重，不更换整体架构，不把多智能体或新增模型当成前置条件。移动端独立规则是另一个认证层级；没有实际手机端证据时只报告未验证。发布、短口令上云及设备推送独立于本地产物完成，不作为本次默认操作。

## Decisions

交互时限在线回归实际等待78秒后得到成功相关回答，但原“只问A/B、不做其他事情”任务被“不做”里的动词误分到实施，门禁要求写文件而failed。另修通用局部否定动词过滤，保留原ASCII词边界；只有否定限制不产生正向执行目标，同句其他正向实施要求保留，实际写入/结构化计划的事实校正不变。该词面过滤仍是初始建议，不宣称完整语义理解或自动处理所有歧义。保留原failed及成功问答收据，新候选另做复验。

完整用户交互检查发现ask_user默认等待300秒、允许至1800秒，但Executor把普通工具统一限60秒，会在正常用户选择前结束。工具外层时限改为有效交互预算+5秒结算余量；无效超时由原交互验证快速拒绝，其他工具60秒和verify_delivery180秒保持原样。此通用修复独立于Commons业务规则；当前在线案例使用修复前私有候选，源码回归与新构建另记，不能把旧候选结果算作新代码实测。

2026-11-04用户纠正验收方式：宿主扮演普通用户，仅给目标和少量背景，由Hub调查并给出证据，再以用户可理解的方案/代价询问；选择后实现、交付，用户侧功能测试的实际反馈再驱动修订。新增4.18验收此完整交互链，使用未做过的Wikimedia Commons视频目标、空项目、当前正式Skill、真实SDK与相关问答ID。初始提示不包含协议、接口、选择器、规则代码或专用裁判。调查/需求选择/用户测试反馈/宿主工具修复分开记录，用户测试可调用生产运行库而不使用桌面；无证据时不得以“内部自测通过”取代用户反馈。不强制已有明确选择的用户重复确认，不把目标专用实现写成通用智能性。Skill修订是用户明确要求的工作流调整，不是自动经验晋升。

2026-11-04用户优先交付：“至少让hub生成一个可用规则”。本轮先恢复动漫共和国既有Hub生成的独立JS交付链，当前生产运行/解码复验与现有云ID只读回验；由当前候选Hub整理可导入文件和简短说明。复用此前Hub原样规则/发布回执时明确为已知资产交付恢复，不伪称从零新生成或一次全自主逆向；云ID仍可用时不重复上传。当前可用产物先交付用户，通用经验晋升不阻塞用户使用。

2026-11-04用户追加方向：尽量减少用户纠错，经验沉淀以通用能力为目标。验收分别记录用户纠错次数、预定业务补充/转向、模型依工具证据自行修复及宿主基础设施修复，不能把新增业务要求算作纠错，也不能隐藏监督者给出的错误反馈。当前4.4的路由、单契约修订、验证时效和来源绑定是通用机制；有限合成回归只证明这些机制的实测切片。后续4.6经验候选应描述失败类别、证据条件、适用范围与可撤回策略，在未用于提炼的不同任务上验证后晋升；任务专有地址、接口、选择器、答案或某个模型的示例解法不直接升级为全局策略。

首轮无profile复验两个实际任务completed（小改动11轮、两文件任务17轮），但补充消息经SDK返回422，不能认证动态交互；另因PowerShell标量splat把续跑标志拆成字符，第三案未执行，单列not_run基础设施错误，原报告all_passed不代表三案通过。修复前先归档原SDK/启动器/回放脚本字节及哈希。

SDK interact沿用后端唯一契约：steer为{action:"steer",response}，respond为{action:"respond",requestId,response}；旧steeringPrompt调用在SDK内映射，旧token/approve因语义不等于requestId不得猜测转换，明确拒绝并保留现有权限边界。补充指令成功入账后使当前验收轮次递增，仅使验证及其依赖步骤/产物收据待复验，保留实际观察与修改事实，不强迫另建计划或重读文件。默认执行阶段和显式要求均已满足时明确建议答复，无交付声明时说明verify_delivery不适用，不事后为它强造计划。修改SDK、状态更新及启动器后另冻v2，原失败/漏跑不回填；新版两文件任务明确要求维护一份可核对计划，属于新措辞受控案例，不冒充原样成对实验。

2026-11-04续推4.4：词面分类只作初始路由。已确认TaskContract的mutation/verification步骤，以及规范化成功的真实变更收据，可以将普通对话/调查推进到执行或只验证模式；不允许模型用计划降低已有执行要求，不改变工具授权、物理/业务验收策略。重分类仅搬运当前Run真实观察、变更、仍新鲜验证的状态，不能凭计划生成完成事实。显式只读任务保留原约束，拒绝带mutation的计划及已识别原生写入/受控发布；任意shell仍不是隔离保证。普通文档无宿主profile时不偷偷启用physical_artifacts。

历史投影按原Run边界给工具结果和旧助手声明添加来源标签；旧工具ID、配对、原文和折叠规则保留，原始SessionLedger/SSE不改写。无Run标记或跨边界不明的旧结果标unknown，不认当前证据。TaskProgress新增当前Run事实摘要，只记录规范化工具名、状态计数、当前收据引用和绑定Session/Run，不把命令正文、路径、文档内容或模型提供提示当作系统事实；摘要有容量上限并在截断时标为下界。历史资料可引用为先前观察，但不能为当前Run补签。SDK复测固定普通无profile小改动、复杂单契约及同会话只读转向；首轮全部保留，不能以此关闭60任务或完整普通文档自动验收认证。

2026-11-04任务范围定点修订：自动词面匹配只推荐Skill目录及读取入口，不将整个正文或全生命周期流程自动升级为本轮必做任务；用户完整点名的Skill优先且加载正文，仍须服从当前用户范围和实际验收。统一worker与Run Prelude的候选发现，显式skill_tool读取返回同一资源及范围提醒。该策略不新增文档关键词分类器、不屏蔽领域工具，也不把候选命中当作实际使用。简单任务直接修改和验收；复杂任务保留一份TaskContract，完全相同的plan_task重传不清除进度或失效验证，实际新要求沿revise_task_plan增量失效相关步骤。先用确定性收据/修订回归，再冻结自然措辞真实SDK文档与实现任务；多轮重定向等完整4.4门槛未经实测不得勾选。

首版范围复验三案2completed/1failed，原文档仍在写入/验收后耗尽10轮。按已固定physical_artifacts策略统一默认认知推进文案与验证阶段名称，删除相冲突的“改动行为/运行代码质量测试”指令，优先文件修改→verify_delivery→有据结题；工具和原门禁不变。普通quality_checks任务保持原推进策略。合成Skill实现的首个验证器错误要求工作副本含默认排除的.agents目录，另建v2裁判仅核对固定原Skill源的同一哈希，保留首次误拒及Hub补拷后的10轮completed；断言函数行为、输入不可变和README不变不降低。旧候选及其冻结审计保持原样，再冻新候选复验。

二版快照证实中文“修订README”被现有意图引擎归为Conversational，不能据此断言已经跑到Execution专属指导；旧全局默认anchor仍要求编译/测试。物理宿主策略的推进提示因此须独立于词面TaskKind，并仅在展示时替换系统默认验证anchor，保留用户显式子任务与自定义约束；收据齐备后明确进入剩余显式步骤或最终答复，避免再重复哈希/验收。不得据此宣称已修复完整自然语言分类。人工复核另发现首版新措辞文档沿用输入README未核实的AST认证为事实，物理oracle通过并不等于正文准确；指导须区分历史文案、用户给定范围与本Run真实收据，未经复验不新增认证。原completed终态不改，人工内容判定单独保留。

2026-11-04下一轮定点恢复：保留既有精确调用循环守卫，网关新增Run内失败台账（只存调用指纹/类别/次数），参数和缺依赖失败不允许原样盲重试；暂态网络、业务及未知失败在同一工作区修订下最多执行两次，成功读探针不能清除失败预算。真实写入/回滚开启新修订，同一调用实际成功才清除自身失败；指导按参数、依赖、网络、业务分别给出下一步，不保存原始敏感错误。此切片不自动安装依赖，也不宣称解决任意参数变化下的语义死循环。

纯文档等物理产物验收由固定宿主profile显式声明completion_policy=physical_artifacts（默认quality_checks不变）；仅允许有必需产物且全部不带业务validator、无受控动作的配置。当前Run全部产物收据和哈希新鲜时可满足默认RunPlan/DoD验证阶段，但不将物理收据改标domain_verified或质量测试，也不跳过显式TaskContract子任务。模型不能通过plan_task自行声明该宿主策略。

保护当前Run的.superagent/traces，原始内部提示和自读trace不作为业务证据。绑定Run的网关对直接文件路径和已观察到的显式shell路径在执行前拒绝，引导read_tool_result和真实业务文件；宿主可在固定profile显式allow_internal_diagnostics=true用于授权诊断。该路径规则不是任意shell/操作系统隔离，不关闭完整4.3。旧报告、规则和云ID保留，本轮复验不新增云发布、不操作桌面或替换安装版。

### D1：沿实际产品入口验证，冻结外部帮助边界

主链为：用户自然请求 → 生产 SDK/LocalGateway → `/api/agents/run` → 真实 worker → 技能/工具 → Hub 写产物 → 生产规则运行库 → 独立验收 → 交付。无界面进程实例化生产组件，保留 SSE、工具、进程和终态记录。CLI `hub ask/chat` 继续明确标记为普通对话；不得用其回复证明具备工具执行。

每次业务评测开始前冻结：源代码/二进制/技能/任务/测试哈希、模型配置标识、目标路径、许可操作、截止时间与预算。首轮使用用户已配置的 `gemini-3.8-flash-high`，只引用已有凭据。任务开始后，宿主只能观察和运行预先冻结的验收器；若人工或 Codex 新写目标专用代码、补充方案或修改测试，该次必须记为 assisted 或 corrected，另起独立首次尝试测试并注明先前教导历史。

选择这条路径是为了覆盖真实接线断点。组件测试继续保留，不能单独代替业务认证；也不通过宿主先生成最终规则再让 Hub 执行来取得通过。

### D2：扩展既有任务契约与收据，不建立第二套任务状态

TaskContract 增加版本化的交付说明，保持旧 Session 可读取；SessionLedger 仍是生命周期事实源，TaskProgress 保存验收进度而非另一套 completed 状态。建议字段如下，具体序列化先写接口文档再实施：

| 对象 | 关键内容 | 所有权 |
|---|---|---|
| 交付目标 | 用户意图、只读/生成/修改范围、目标身份、必需与可选成果、验收项、预算 | 模型提出，运行时校验授权和结构 |
| 产物记录 | Run/Session、绝对路径、SHA-256、作者/复用来源、依赖、源指纹、生成时间 | 运行时读取真实文件产生 |
| 验证记录 | 验收项、产物哈希、验证器版本、实际输入、退出码、领域断言、时间和适用范围 | 受信任验证器产生 |
| 结题说明 | 已完成、未完成、抽样范围、运行要求、失败原因、后续入口 | 从以上事实生成，模型补充解释 |

模型文本、计划勾选、文件名、单次 exit 0 均不足以证明业务通过。验证后产物改变，原验证自动失效；只读调查不要求制造无关代码修改。仅可选增强失败时允许交付主成果并明确标注；必需项失败时不能标记业务交付完成。

保留现有 Observation/Mutation/Verification/UserInput 分类，补充证据来源和作用域约束。需要重新执行的失败进程不能伪装成功观察；一次媒体解析不推广到分页、全目录和持续稳定性。此方案优于继续增加“完成关键词”和命令文件名白名单。

### D3：先交付动漫共和国的可执行纵向切片

第一业务对象固定为 `D:\太极\动漫共和国概念版`，校验安装文件和 DLL 身份。原应用目录只读，临时状态及生成物放独立输出工作区，不读取原账号状态。允许复用已有 `local-app-inspector/scripts/dmghg_probe.py`，并在报告中标明是既有资产。

Hub 必须自行新增并交付：

1. 可导入的海阔规则 JSON 及其源码；分类、列表、搜索、详情和选集 lazy 链路使用原目标数据。
2. 如纯 JS 不能直接访问 Windows 原生接口，Hub 编写最小本地桥接适配层，暴露有界、版本化的本地接口，处理并发、超时及关闭。优先衔接既有端侧引擎，禁止另起云端凭据代理。
3. 运行说明和依赖清单，明确需要 Windows 原应用资源/本地服务，以及手机独立版是否存在。
4. 由受信任验收器生成的产物清单、规则执行记录和媒体检测报告，包含哈希及样本范围。

逐层验收：

| 层级 | 必须通过的检查 | 不能替代它的结果 |
|---|---|---|
| A：产物 | Hub 写出的文件存在且可解析；目标身份与来源正确 | 只有计划、报告或别人预写脚本 |
| B：规则执行 | 无界面调用生产规则执行库，走一级→搜索→详情→lazy；真实返回非空业务数据 | 仅 `validate-rule` 静态通过或简化模拟器高分 |
| C：数据完整性 | 两个分类、两个自然关键词；列表第一页与下一页区分；详情前/中/后选集与上游同次数据一致 | 固定一部剧、第一页抽样被称全站支持 |
| D：媒体可用性 | 从规则的 lazy 结果发起媒体请求，并用无音视频输出的解码器读取真实参数及至少 1 秒推进；检查空流和过期结果 | 探针另取播放地址、只看 HTTP 200 或后缀 |
| E：可重复交付 | 新输出目录、清空本次缓存、仅依赖清单启动，连续三次独立 Run 完成；失败原样记录 | 重用上次成功产物或手动修规则后沿用原成绩 |

分页能力先测原接口实际语义；确实无分页的频道需提供上游证据并声明不适用，不能伪造第二页。单个目录不适用不能把所有分类分页都豁免。若目标接口变化致无法取得样本，记录 blocked 并保留证据，不临时改换网站冒充原应用转换。

外部媒体的暂时性故障可使用预先冻结的有界重试：最多三次，对同一实际lazy返回值和请求头进行独立的16秒解码，不换影片、不修改地址、不累计进度。一次实际解码须超过1秒才通过；成功和失败都保存所有尝试。原Run失败不回填，总验证及模型预算不扩展，三次独立生成仍须各自满足A–E。

“完全不需要桌面参与”指没有界面操作。以上本地桥接仍可能依赖本机进程，这个依赖必须明确。PC 链路完成不能代替 Android 实机认证；纯手机独立版需另行证明协议、依赖可移植性和设备端运行。本阶段不自动推送手机、不生成未经真实上传的口令。

### D4：技能成为可执行契约，保留现有 Markdown 兼容

用户已追加授权监督Hub完成现有独立JS规则的实际云剪切板发布。此阶段允许上传该规则源码，不包含模型凭据、用户账号、安装目录或设备推送；不新建付费账号或长期服务。输入规则固定SHA，监督者准备独立裁判但不替Hub编写/执行发布程序。上传成功立即转回读，不为评测重复创建副本；失败按服务记录，单服务相同错误不盲目重试。口令验证使用生产解析器和私有临时数据库，比较规范化后必要字段哈希。首次和反馈后的记录分开，不能由本阶段推导完整逆向端到端自主或自动晋升能力。

本次独立JS切片的人工复盘可整理为有来源的Skill候选参考，记录已知目标证据、运行时边界、共享代码输出限制、媒体负例和真实云发布回读要求。此类人工整理不等于Hub自动结晶、留出任务泛化通过或P7自动晋升。仅询问发布能力不自动上传；用户明确请求发布时按其选定服务及范围执行，上传后须回读并用实际导入器验证内容。

#### P2目标纠偏：独立JS直连接口

2026-11-03用户要求应用逆向产物为独立JS规则。安装路径仅是调查材料，发现原生C ABI不能自动改变交付依赖。默认先还原应用实际请求的域名/路由/方法/参数/公开协议签名和响应解密；只提取地址或持久化短期媒体链接不算完成。探针/DLL可在隔离调查中作原目标对照，最终规则必须仅通过目标海阔支持的JS及网络接口运行。调查工具所用语言与用户运行时依赖分开记录。不得用Node调用DLL、改写成本地JS服务或打包EXE冒充独立规则。

旧v21的三次桥接验收保留，不回写失败，也不能升级为JS独立认证。新验收在无桥接进程、无本机端口、无安装目录/DLL可访问依赖的规则执行环境检查分类、分页、搜索、详情、实际lazy和真实媒体；Android仍需实际平台证据。若协议尚未还原，应记录具体缺口与可重复证据，不宣称只能桥接或纯JS已可用。只有用户明确选择有依赖方案时才交付常驻桥接。

在现有发现、去重和资源读取基础上，增加可选版本化清单，描述适用任务、依赖、资源、预期产物、运行时范围和验证器引用。无清单的旧 Skill 可运行，但没有声明/完成领域验收不得获得业务认证。

验证器分两层：技能自带检查反馈语法与快速错误；宿主维护的独立验证器检查实际任务目标、来源、数据和运行。模型可以修规则及适配器，不能修改本次冻结的验收器或把验证目标改成替代站点。技能脚本名含 validate 不自动成为受信任业务裁判。

缺依赖时先判明可安装范围和替代方案，在临时作用域试装并验证，不能静默改变全局环境。新技能或修订先成为候选，经契约检查、负例和留出集后才能晋升；保留版本、原始失败、来源及回退入口。

规则工程 Skill 中“双端完美运行”“沙箱五星”“自动推送”等强表述，需要改为按真实证据认证和按用户授权执行；先更新相应规范，再修改提示与脚本。防止把技能文字当成已经实现的底层能力。

### D5：理解与规划根据缺口推进，避免反复写计划

保留单一结构化任务契约。简单单产物直接实施并验证；复杂任务维护不超过既有预算的依赖步骤，遇到新证据更新受影响部分。明确“只调查”“先调查再修改”“生成可用规则”“继续上个任务”的区别，覆盖不同说法、否定和多轮转向；不再以增加关键词分支作为主要提升方式。

每次动作应对应一个未解决问题或验收缺口。失败时读取完整错误，区分参数/工具/依赖/网络/业务/权限，再选择重试、换方法、重规划或报告阻塞；同一输入无新证据最多重试两次。每 Run 明确轮数、总时限、模型调用预算，嵌套工具计入总预算，预算耗尽交付已有成果和剩余问题，不写成功。

优先验证超长输出的写入和 `read_tool_result` 读取是否共享同一 Run 作用域，保证错误末尾和关键字段能找回；禁止依靠摘要猜测完整失败信息。完成复核保持有界，不能通过无限自我对话隐藏失败。

### D6：让知识能力按任务提供有效证据

| 能力 | 预期工作方式 | 验收方法 |
|---|---|---|
| 原生 understand/图谱 | 结构问题优先图谱，带源指纹与索引版本；变更后按影响范围失效 | 植入跨文件依赖，检查影响结论和实际修改；陈旧索引必须刷新或降级 |
| 外部 Understand | 与原生能力分别列出 registered/available/ready/validated 状态 | 独立安装/资源/查询测试，未验证不显示已认证 |
| Supermemory | 项目+来源+时间+置信度+适用版本；事实/偏好/失败经验分型；错误记忆可撤销 | 跨 Run 复用必要事实；重启后可检索；另一项目和过期冲突记忆不误用 |
| RTK | 记录真实调用和输入/输出字节；保留退出码、错误、产物引用，允许取回原文 | 长日志对照压缩率与任务正确性；短输出 0 收益正常，不强制压缩 |
| 需求引擎 | 产出可执行影响分析和计划并交回实施流程 | 原需求→计划→代码→验收关联；仅计划的任务不能标记代码已完成 |

先解决作用域：区分 origin 的只读知识源和隔离执行根，写盘、命令、清单和验证都绑定已授权输出根；保留使用 origin 知识的能力。代码图谱 MCP 不可用时向原生图谱或定点源码降级，不能空结果伪装成“没有影响”。

知识命中不自动表示有收益。对同一冻结任务做有/无图谱、有/无记忆、有/无压缩的成对实验，记录正确率、检索定位时间、token、耗时；工具显式调用或经过来源归属核对的 Prelude 注入都算参与，不要求模型为得分重复调用。密钥、Cookie、会话和签名媒体链接不沉淀进可召回经验。

### D7：固定评测与对话教导，检验迁移而非背题

既有五项 Golden Evals 的 100% 发布门槛保留。另新增业务套件，避免用这五项替代真实能力；离线确定性测试、在线自然任务和外部环境可用性分别报告。

第一版固定 20 个案例，每例三种自然措辞，共 60 个任务，全部进入分母：需求分类/延续 3 例，正向实现 4 例，逆向理解 3 例，真实规则生成 4 例，失败恢复 4 例，记忆迁移 2 例。每例有冻结的验收和来源，含负例；其中未见目标/结构的留出样本不用于提示修补。至少 10 个任务作为真实业务关键子集。运行前冻结任务、模型和技能身份，未达到预算时不挑成功重放覆盖旧记录。

具体案例草案如下，均为待建/待冻结的评测，不代表已经通过。F03、R02、H03、H04 作为案例级留出集，三种措辞全部留出；P0 固定实际输入、独立断言和关键子集身份。

| ID | 用户任务/触发 | 独立验收重点 |
|---|---|---|
| U01 | 只复核已有应用调查报告 | 结论有来源，不改业务代码，不要求生成规则 |
| U02 | 先调查故障，再修复 | 两阶段均完成；调查成功不提前结题 |
| U03 | 中途补充限制后要求继续 | 保留目标和已有成果，遵守最新限制，不从头重复 |
| F01 | 修复边界条件及相邻输入 | 冻结的边界/反例测试通过，无无关修改 |
| F02 | 修复前后端字段类型不一致 | 两侧契约一致，生产请求路径通过，文档和台账同步 |

三条评分通道分开：

- first_attempt：宿主未提示具体方法或补写目标代码；包括公开旧技能的正常复用，并明确复用程度。
- corrected/assisted：提供纠错反馈、人工方案或宿主增补专用代码后完成；保留纠错前失败。
- blocked/infra_failed：外部不可用或环境失败；不能从总体分母静默删除，同时另报可执行子集成绩。

教导流程是“自然需求→首次执行→独立指出一个可验证错误→Hub 修正→新措辞/新目标验证→候选经验→留出集→晋升”。首次尝试、对话纠错能力、学习后迁移三列独立，明确不是模型权重更新。

| 指标 | 首个推广门槛 | 后续目标及解释 |
|---|---|---|
| 目标业务切片 | DMGHG 三次独立连续完整通过 A–E | 每次安装/上游身份保留，不推及其他应用 |
| 真实业务关键子集 | 首次尝试 ≥8/10，且所有失败保留 | 扩样后争取 ≥90%，报告样本数和区间 |
| 完成真实性 | 必需证据缺失时误报完成 0 次 | 作为硬门槛；“未观察到”不等于不存在风险 |
| 不相关写入 | 受测源目录、其他项目、冻结验收器发生未授权变更 0 次 | 所有晋升与发行沿用此门槛 |
| 可恢复失败 | 固定 4 类恢复案例逐项通过 | 扩样目标 ≥90%，不将无条件网络可用算智能 |
| 知识收益 | 成对比较无正确率下降，并记录成本 | 依据基线确定优化幅度，不承诺所有任务更快 |
| 时延和成本 | 记录 p50/p95、token、模型/工具耗时 | P0 取得基线后冻结具体预算；不靠无限重试过关 |

日常仅运行受影响的确定性回归；改动某业务链时跑小规模在线集；候选发行再跑完整 60 任务及关键业务重放。新失败、变更和风险才触发扩大回归。

### D8：把进化分成经验晋升和代码升级两种路径

先完成经验与技能晋升，再考虑代码自修改。现有 request_reload 返回重启请求已发出，不能当成新版本健康；现有 supervisor 的源码备份/重编译方式不作为安全升级的验收依据。

代码进化必须：固定基线和未提交改动快照 → 隔离 checkout/目录中生成限定补丁 → 编译候选二进制 → 独立回归、留出集和健康检查 → 执行版本化切换 → 确认新进程身份及会话连续性。失败只撤销候选及切换，不恢复/覆盖整个用户 `src`。有活动 Run 时采用排空或显式支持的恢复协议，不能终止任务后伪报持续运行。

晋升门槛包括无质量退化、无作用域扩张、成本预算内、有可执行回退。自动晋升权限按既有用户授权配置，不把“学习”解释成自行取得新权限。暂不引入多智能体并发或全局自动热更新，以免在可靠性基线不明时扩大故障面。

| 阶段 | 依赖/估算 | 主要落点 | 交付与退出门槛 |

## Risks / Trade-offs

- [上游应用/API变化] → 固定本次版本和源指纹；过期证据失效；失败报告区分环境与推理，目标不偷偷换站。
- [Skill 强承诺超出现有能力] → 先修正文档契约，认证桌面运行库与 Android 分开；模拟器不能代替实机。
- [提示膨胀增加成本、规则互相冲突] → 复用单一任务契约，按能力按需注入；比较有无上下文的正确率与耗时。
- [验证器和模型一起犯错] → 冻结独立验证器、负例和目标身份；验证器修复需保留原判并重新审计，不回填早期成绩。
- [线上评测有随机性及费用] → 固定样本和预算，首轮全部保留，分批运行；配置只记录非敏感身份，不复制密钥。
- [隔离强化可能影响现有 origin 记忆命中] → 明确只读知识源和执行根分工，补两种目录的正反测试，不简单禁用项目知识。
- [自升级误伤未提交代码和活动任务] → 最后实施、限定补丁、候选二进制隔离、排空与回退；禁用整目录源码恢复路线。
- [多阶段范围较大] → 同一提案表达终态，每阶段有独立退出门槛；必要时按已冻结契约拆分后续子变更，不能绕过已批准规范。

## Migration Plan
