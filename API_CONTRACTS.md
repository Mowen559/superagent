# Hub-RS API Contracts

## POST /api/analyze/wiki

Generates one unified project knowledge-chain view from the indexed code graph, Knowledge Corpus documents, current Git status, and DeepCloud AI snapshot history.

Request:

```json
{
  "project": "D:\\mowen\\deepcloud",
  "lang": "zh-CN"
}
```

Response:

```json
{
  "success": true,
  "project": "D:\\mowen\\deepcloud",
  "indexed": true,
  "wiki": "# Project Wiki...",
  "trace": {
    "project": "D:\\mowen\\deepcloud",
    "graphDb": "...db",
    "indexed": true,
    "overview": {},
    "files": [],
    "symbols": [],
    "documents": [],
    "git": {
      "status": {},
      "aiHistory": [],
      "changedFiles": {}
    }
  },
  "generatedAt": "2026-09-01T00:00:00Z"
}
```

Notes:

- `project` must be the same workspace path used by `POST /api/projects/analyze`; the graph DB path is derived from this value.
- `wiki` is generated by the configured LLM when available. If no LLM is configured, the endpoint still returns a deterministic Markdown fallback and the full `trace`.
- The generated wiki is persisted as a project-scoped Supermemory record with id `project-wiki-latest`.

## Workspace Intelligence API

The workspace API is the preferred UI-facing contract. It composes project indexing, graph understanding, Supermemory, reverse planning, and shadow Git into one project workspace model.

### POST /api/workspaces/open

Validates and registers a workspace path for the current local control-plane process, then returns derived runtime locations and bounded `readiness` facts. Subsequent workspace analysis, Agent execution, Knowledge Corpus and Apply operations consume this registered canonical path.

```json
{
  "path": "D:\\mowen\\deepcloud"
}
```

The response includes:

```json
{
  "workspace": {
    "path": "D:\\mowen\\deepcloud",
    "readiness": {
      "kind": "code-project",
      "canAnalyze": true,
      "canRunAgent": true,
      "filesScanned": 155,
      "languages": { "Rust": 87 },
      "warnings": []
    }
  }
}
```

### POST /api/workspaces/analyze

Starts a shared, cancellable project-analysis task. Completion means the indexer exited successfully, the graph database passed schema validation, and a structured Project Analysis Receipt was persisted. LLM overview generation is optional and degrades to a receipt warning when unavailable.

```json
{
  "path": "D:\\mowen\\deepcloud",
  "projectId": "deepcloud",
  "language": "zh-CN",
  "model": "gpt-5.6-sol"
}
```

Response:

```json
{
  "taskId": "...",
  "status": "submitted",
  "workspace": {
    "path": "D:\\mowen\\deepcloud",
    "graphDbPath": "...",
    "memoryPath": "D:\\mowen\\deepcloud\\.supermemory\\supermemory.json",
    "shadowGitPath": "D:\\mowen\\deepcloud\\.shadow-git",
    "indexed": true
  }
}
```

`POST /api/projects/analyze` accepts the same project path plus an `options` object:

```json
{
  "path": "D:\\mowen\\deepcloud",
  "projectId": "deepcloud",
  "options": {
    "language": "zh-CN",
    "includeLlmOverview": true,
    "timeoutSeconds": 900,
    "maxInventoryFiles": 50000,
    "maxFingerprintBytes": 67108864
  }
}
```

Unknown option fields are ignored for compatibility. Limits are bounded by the server. The final `GET /api/tasks/{taskId}` response carries `receipt`, including graph totals, project inventory, source fingerprint, warnings, and the exact LLM-overview outcome. Cancelling through `POST /api/tasks/{taskId}/cancel` terminates the shared analysis task and its indexer process.

### GET /api/workspaces/intelligence

Returns the current workspace intelligence snapshot for display.

```http
GET /api/workspaces/intelligence?project=D:\mowen\deepcloud&limit=24&model=gpt-5.6-sol&refresh=true
```

Includes:

- `workspace`: derived graph, memory, and shadow Git paths.
- `analysis`: the newest shared analysis Task for this canonical workspace, including its receipt when completed.
- `graph`: current indexed project overview from codebase-memory / understandanything.
- `supermemory`: latest project wiki, latest project overview, recent reverse blueprints, memories, knowledge documents, and logs.
- `git`: current Git status and DeepCloud shadow snapshot history.

The default GET is read-only. Passing `refresh=true` explicitly synthesizes or regenerates the Wiki from graph overview, Supermemory, knowledge documents, Git status and shadow history, then persists it into project-scoped Supermemory. Passing `model` uses that model for this request without changing global LLM settings.

The UI must first call `POST /api/workspaces/open`, then automatically load this snapshot whenever the active workspace changes. `analysis` is the resumable Task state and is never inferred from graph-card counts.

### Workspace Knowledge Corpus

- `GET /api/workspaces/knowledge?project=...&q=...&limit=...` lists documents and, when `q` is present, returns scored chunks with Citations.
- `POST /api/workspaces/knowledge/ingest` accepts `{ project, path, globalContext? }` and returns an idempotent Ingest Receipt.
- `POST /api/workspaces/knowledge/rebuild` accepts `{ project, documentId? }`; omitting `documentId` rebuilds all documents.
- `POST /api/workspaces/knowledge/remove` accepts `{ project, documentId }` and returns a Removal Receipt.

All document paths must resolve inside the opened Workspace. Text/Markdown, DOCX and PDF follow the existing bounded Knowledge Corpus rules.

### Agent Task observation, verification and Apply

- `GET /api/agents/tasks/{taskId}/events` replays sequenced persisted events and follows live events over SSE.
- `POST /api/agents/tasks/{taskId}/interact` accepts correlated user responses or steering.
- `POST /api/tasks/{taskId}/cancel` commits `cancelled` and terminates the Adapter.
- `GET /api/agents/tasks/{taskId}/diff` requires a completed Agent Task and returns `{ diff, files, conflicts }`, where each file has `path` and `kind`.
- `POST /api/agents/tasks/{taskId}/verify` runs the bounded automatic quality plan in the isolated directory and persists a Verification Receipt.
- `POST /api/agents/tasks/{taskId}/apply` accepts `{ files?: string[], force?: boolean }`. It only applies files from the latest Change Set Receipt, handles deletions, creates a pre-apply shadow snapshot and persists an Apply Receipt. Verification must have passed unless `force=true`.

The UI must not expose Apply while the Agent Task is running. A forced Apply is an explicit user decision and must never be inferred from an empty or unavailable verification plan.

### POST /api/workspaces/reverse-plan

Runs the reverse-engineering pipeline for a requirement inside the workspace.

```json
{
  "project": "D:\\mowen\\deepcloud",
  "requirement": "Add workspace intelligence orchestration",
  "language": "zh-CN",
  "limit": 8,
  "model": "gpt-5.6-sol"
}
```

The result contains requirement schema, matched existing project context, architecture blueprint, development tasks, and trace evidence. The blueprint is also persisted into Supermemory as `blueprint-{traceId}`.

### GET /api/workspaces/memory

Lists or searches project-scoped Supermemory.

```http
GET /api/workspaces/memory?project=D:\mowen\deepcloud&limit=50
GET /api/workspaces/memory?project=D:\mowen\deepcloud&q=auth&limit=20
```

### GET /api/workspaces/shadow-history

Returns the DeepCloud AI snapshot chain from `refs/deepcloud/ai-history`.

```http
GET /api/workspaces/shadow-history?project=D:\mowen\deepcloud&limit=50
```

### POST /api/workspaces/shadow-snapshot

Creates a new shadow Git snapshot for the current workspace state.

```json
{
  "project": "D:\\mowen\\deepcloud",
  "message": "Manual workspace checkpoint"
}
```

## Visual Pipeline

视觉接口采用稳定的 `Screenshot -> OCR -> Translation` Provider 契约。所有 JSON 字段使用 camelCase；读取 Provider、Settings 和 Monitor 不触发截图、OCR、联网或模型调用。

- `GET /api/vision/providers`：返回按 `screenshot | ocr | translation` 分组的 Provider 元数据、来源、就绪状态与配置要求。
- `GET /api/vision/settings`：返回当前 Provider 选择、PaddleOCR 模型文件路径和默认翻译语言，不返回密钥。
- `PUT /api/vision/settings`：原子更新上述非秘密设置；Provider ID 必须属于对应阶段。
- `POST /api/vision/providers/reload`：重新扫描 `app_data_root/vision/plugins/*.json`，不会执行插件。
- `GET /api/vision/monitors?providerId=xcap`：显式查询截图 Provider 的显示器清单。
- `POST /api/vision/capture`：接受 `{ providerId?, monitorId? }`，返回只能通过 UUID 读取的 PNG Artifact。
- `GET /api/vision/artifacts/{artifactId}`：只读取 Hub Artifact Store 中的 UUID PNG，不接受文件路径。
- `DELETE /api/vision/artifacts/{artifactId}`：显式删除截图；Artifact 默认最多保留 64 个且 24 小时过期。
- `POST /api/vision/ocr`：接受 `{ providerId?, artifactId }`，返回文本块、置信度、Provider 与耗时。
- `POST /api/vision/translate`：接受 `{ providerId?, text, sourceLanguage?, targetLanguage, model? }`，返回译文、Provider 与耗时。
- `POST /api/vision/pipeline`：接受截图参数、三个可选 Provider ID 和翻译参数，顺序执行三段并返回 Visual Pipeline Receipt。

内置 Provider：`xcap`、`paddleocr-rs`、`hub-llm`、`deepl`、`google-translate`。PaddleOCR-rs 从设置中的 detection/recognition/keys 文件加载 ONNX 模型，不自动下载。DeepL 使用 `DEEPL_API_KEY`，Google 使用 `GOOGLE_TRANSLATE_API_KEY`，Hub LLM 复用现有模型账户和路由，因此 Gemini/GPT 不在视觉模块重复保存凭据。

外部插件 Manifest 示例：

```json
{
  "schemaVersion": 1,
  "id": "scap",
  "kind": "screenshot",
  "displayName": "scap screen capture",
  "executable": "C:\\tools\\hub-scap-provider.exe",
  "args": [],
  "timeoutSeconds": 30,
  "enabled": true
}
```

Hub 向插件 stdin 写入单个 JSON 请求，插件在 stdout 返回单个 JSON 对象。Screenshot 插件把 PNG 写入请求给定的 `outputPath`；OCR 插件接收 `imagePath` 并返回 `{ text, blocks? }`；Translation 插件接收语言与文本并返回 `{ translatedText }`。超时、非零退出、过大输出或非法 JSON 均返回带失败阶段的 Provider 错误，不生成成功 Receipt，也不回退到未经用户选择的联网 Provider。

## SuperAgent SDK 协议规范与契约基线

SuperAgent 采用 **“Sidecar/守护进程 (Rust Hub-RS) + 标准开放契约 (OpenAPI 3.1 & MCP) + 多语言客户端 SDK”** 架构，为 DeepCloud 微服务、前端及外部系统提供统一调用契约。

### 1. OpenAPI 规范与文档端点
- `GET /api/openapi.json`: 输出标准 OpenAPI 3.1 规范定义，供 Java (openapi-generator)、TypeScript (Orval)、Python (openapi-python-client) 自动生成强类型 SDK 代码。
- `GET /api/docs`: 内置轻量交互式 API 浏览器（基于 Scalar API Reference），支持本地在线调试与接口查看。

### 2. 五大 SDK 核心能力面契约
1. **ModelGateway**:
   - `POST /v1/chat/completions`: 兼容 OpenAI Chat 格式，支持流式 SSE、多 Provider 故障转移与 Token 计量。
   - `GET /v1/models`: 查询当前 Hub 实例所有有效模型。
2. **AgentExecution**:
   - `POST /api/agents/run`: 异步分派自主智能体任务，返回 `taskId` 与 `eventsUrl`。
   - `GET /api/agents/tasks/{task_id}/events`: 标准 SSE 长连接，按序列推送 Agent 决策、思考、工具调用与步骤状态。
   - `POST /api/agents/tasks/{task_id}/interact`: 提交人类在环 (HITL) 决策令牌审批，或向运行中的任务实时插队追加 Steering 指令。
   - `POST /api/tasks/{task_id}/cancel`: 优雅终止运行中任务并回收进程与工作区资源。
3. **DiffAndVerification**:
   - `GET /api/agents/tasks/{task_id}/diff`: 获取影子沙盒（`.shadow-git`）中的变更文件列表与 Unified Diff 补丁。
   - `POST /api/agents/tasks/{task_id}/verify`: 执行自动化质量计划（包含阿里 OCR 确定性规则质检）。
   - `POST /api/agents/tasks/{task_id}/apply`: 创建预应用快照并安全打入宿主工作区。
4. **WorkspaceIntelligence**:
   - `POST /api/workspaces/open`: 打开并校验工作区根路径。
   - `POST /api/workspaces/analyze`: 触发项目代码知识图谱与依赖关系索引。
   - `GET /api/workspaces/intelligence`: 获取工作区全景快照、AST 符号拓扑与爆炸半径分析。
   - `GET /api/workspaces/knowledge`: 语义检索项目 Wiki 与规范语料（带 Citation 溯源）。
5. **SystemAndHealth**:
   - `GET /api/health`: 探测服务存活、内存负载与上游 Provider 延迟。
   - `GET /api/capabilities`: 动态发现当前 Hub 启用的功能模块。
