# 需求理解与执行证据闭环

基线：`feature/ai-core-workbench@80b1f75`。变更规范、技术决策和任务位于 [OpenSpec 变更](../../openspec/changes/evolve-task-understanding-evidence/design.md)。本设计使用当前分支的官方 OpenSpec 流程，不替换现有网关、追踪、工具归一化、思考等级与回滚机制。

## 行为与接口

复杂任务通过 `plan_task` 保存目标、验收、约束、依赖子目标和待查问题；简单任务直接执行。Prelude 只投影当前工作区实际文件，保留路径、行号与截断标记；不能由 Maven/前端清单推断具体框架规则。事实问题先调查，确有影响范围或行为的用户选择再询问。

`update_task_progress` 用当前 Run 的收据 ID 绑定步骤和问题。收据须成功、类型/来源匹配、依赖满足且仍有效。Todo、规划和进度工具不产生代码修改或验证证据，模型文字也不能关闭步骤。

`revise_task_plan` 使用 `base_revision` 加追加条款与局部步骤更新。省略字段和原依赖保留；不允许增量删除要求、弱化证据类型或制造循环。校验失败保持原状态，重复相同增量不推进版本。变更步骤和后续依赖需要新收据，新增要求重开验证。完整替换会清空绑定；工作区回滚保留要求但清除全部已绑定进度与缓存收据。

预算：12 个步骤、12 条验收、16 条约束、8 个问题，规范化完整 JSON 12,000 字符；收据元数据缓存 256，每次绑定最多引用 8 个收据。超限报错，不静默删减用户要求。

## 验收与失败

Gateway 在别名/参数归一化后、结果压缩前判定退出码与失败状态。只有明确前台质量命令成功退出才能形成验证；普通读取、后台启动、帮助和进程工具正常返回均不足。后续修改、失败检查或追加要求使旧验证失效；质量检查不能自行推进工作区代次，修改后可以合法复验。

顺序和并行分支消费完整收据。正文、清单完成及历史答复候选都经过同一个完成入口；最多一次复核，Fast 模式不能绕过，无证据或轮次耗尽失败收敛并记录失败经验。保留现有工作区回滚，并清除回滚前的完成事实。明确的只做方案请求可以交付有调查依据的提案，不能称未来步骤已执行。

## 评测与限制

离线预览不读取模型凭据、不联网：

```powershell
cargo run --locked --example task_understanding_eval -- --case steered-log-plan
```

显式真实模型评测使用 `--live`、可选 `--model` 与 `--output`；每请求最多 1,536 输出 Token，每配置最多 4 轮，只提供合成资料，保存实际模型身份、配置、夹具指纹、错误轨迹和用量。默认不运行收费评测。

收据与结构通过不等于用户语义全覆盖或真实业务验收通过；词面匹配和原条款逐字保留都不是成功率。本轮不交付五项领域 Golden Evals 总脚本，也不实现跨进程 TaskProgress 恢复，能力继续为 Experimental。
